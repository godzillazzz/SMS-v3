# UI/UX Audit — sms.xvela.app (2026-10-27)

ตรวจจากเว็บจริง `https://sms.xvela.app` ด้วยบัญชีผู้ดูแลระบบ ที่ Desktop 1440×900 / 1280×800 และมือถือ 375×812
ตรวจแบบอ่านอย่างเดียว ไม่ได้บันทึก อนุมัติ หรือแก้ข้อมูลใด ๆ

> **หมายเหตุสำหรับผู้แก้:** build ที่ deploy อยู่ไม่ตรงกับ `main`
> เว็บจริงใช้ฟอนต์ `Inter` และมีคลาส `.attendance-device-admin-events`
> แต่ใน `main` ฟอนต์ตั้งไว้เป็น `IBM Plex Sans Thai` (`frontend/src/design-system.css:5`) และไม่มีคลาสนั้น
> ให้ตรวจก่อนว่า production build มาจาก branch/commit ไหน แล้วค่อยแก้บนโค้ดชุดนั้น

## แนวทางแก้ที่แนะนำ

1. **วันที่:** ทำ date input ของระบบเอง หรือ wrapper ที่แสดง `วว/ดด/ปปปป` แบบ พ.ศ. แล้วใช้ formatter เดียวกับที่ใช้ในตาราง
2. **ฟอนต์:** ให้ `--font-sans` ขึ้นต้นด้วยฟอนต์ไทย (`"IBM Plex Sans Thai"`, `"Noto Sans Thai"`) ก่อน `Inter`, preload ไฟล์ฟอนต์ และลบจุดที่ override เป็น `Inter`
3. **ขนาดตัวอักษร:** กำหนด type scale 12 / 14 / 16 / 18 / 22 / 28px เป็น token แล้วแทนค่าเศษทั้งหมด ขั้นต่ำ 12px และ badge กับปุ่มเล็กใช้ 12px
4. **การโหลด:** แสดง page shell + skeleton ทันทีแทนโลโก้เต็มจอ โหลดแต่ละส่วนแยกกัน และไล่ดูว่า API ไหนของหน้าลงเวลา / ผู้ใช้ที่ช้า
5. **ฟอร์มป๊อปอัป:** สร้าง component กลาง `Modal` (หัว + ไอคอน, ส่วนแบ่งหมวด, footer ติดล่าง, ปุ่มหลักสีเดียวกัน) แล้วย้ายทุกฟอร์มมาใช้
6. **มือถือ:** ตั้ง `font-size: 16px` ให้ input / select / textarea ที่ `max-width: 768px` และยุบตัวกรองบนมือถือเป็นปุ่ม "ตัวกรอง" ปุ่มเดียวที่เปิด bottom sheet
7. **dropdown หน่วยงาน:** เปลี่ยนเป็น combobox ที่ค้นหาได้ แสดง "รหัส — ชื่อเต็ม" และตรวจข้อมูลรหัสรวมในฐานข้อมูล

## สิ่งที่ปกติดี
- ไม่มีหน้าไหนที่ต้องเลื่อนซ้ายขวาที่ 1440px
- หัวข้อหน้าขนาด 22px เท่ากันทุกหน้า
- กด Esc ปิดฟอร์มได้, บนมือถือฟอร์มเต็มจอและ footer ติดล่าง, บน Desktop ฟอร์มกว้าง 760px จัดสองคอลัมน์
- เมนูมือถือเลื่อนดูได้ครบ และส่วนบัญชีผู้ใช้ติดด้านล่าง

## ยังไม่ได้ตรวจ
- ฟอร์มในหน้าอื่นนอกจากเพิ่มพนักงานและเพิ่มใบอนุญาต
- flow การส่งข้อมูลจริง (ไม่ได้ submit)
- หน้าตาเมื่อล็อกอินด้วยบทบาทอื่น (ตรวจเฉพาะผู้ดูแลระบบ)
- Light theme
